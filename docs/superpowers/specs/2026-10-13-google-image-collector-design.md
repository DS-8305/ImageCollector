# 네이버·구글 이미지 수집 개선 설계 초안

작성일: 2026-10-13 (Asia/Seoul)
상태: 검토용 설계 초안. 제품 코드 구현과 실제 구글 수집 검증은 후속 작업이다.
기준 코드: DS-8305/ImageCollector, master, 7be44cfdecc2e7e7f87906227383aea36a214343.

## 1. 목표와 전제

사용자가 요청한 목표는 기존 네이버 이미지 수집기에 구글 이미지 다운로드를 추가하는 것이다. 이미지의 용도는 블로그·영상 제작용 자료 수집으로 확인되었다.

다음 항목은 이 초안을 위한 제안이며, 사용자가 이미 확정한 요구사항은 아니다.

- 기존 Python/Tkinter 데스크톱 앱과 CLI를 계속 사용한다.
- 구글도 단일 키워드와 CSV/XLSX 일괄 검색을 지원한다.
- 첫 버전은 별도 API 계약 없이 Selenium/Chrome을 활용한다.
- 네이버의 기존 기본값은 유지한다. 구글은 제작에 사용할 고해상도 이미지 저장을 기본으로 제안한다.
- 일일 수집량은 아직 확인되지 않았다. 완전 무인 대량 수집을 보장하는 설계로 취급하지 않는다.

성공 기준은 같은 입력 파일을 네이버 또는 구글에 사용할 수 있고, 제작에 맞는 크기의 이미지를 수집하며, 실제 품질·출처·성공 여부를 구분하고 실패나 재검색 때문에 이전 결과가 없어지지 않는 것이다. 저장 수뿐 아니라 고해상도 저장 수와 썸네일 대체 수를 별도로 표시한다.

## 2. 조사 결과와 방식 선택

2026-10-13에 Google 공식 문서를 확인했다.

- Custom Search JSON API는 신규 고객에게 제공되지 않는다.
- 기존 고객의 대체 솔루션 전환 기한과 서비스 종료일은 2027-01-01이다.
- 따라서 신규 Google 이미지 수집 기능의 기본 의존성으로 채택하지 않는다.
- Google은 프로그램·검색 스크래퍼 등의 자동화 트래픽에 비정상 트래픽 메시지와 reCAPTCHA를 표시할 수 있다고 설명한다.
- 검색 결과에 표시된 사용 권한 정보는 원본 사이트의 라이선스를 확인하기 위한 정보다. 다운로드 성공을 재사용 허가로 표시하지 않는다.

| 접근 방식 | 장점 | 제약 | 이 프로젝트에서의 판단 |
| --- | --- | --- | --- |
| Selenium 기반 Google 수집기 | 현재 Chrome·Selenium 구조를 재사용하고 별도 검색 API 계약 없이 시작 가능 | DOM 변경, 동의 화면, 확인 화면 등에 대응 필요 | 로컬 데스크톱 사용을 전제로 우선 추천 |
| 외부 검색 결과 API | 검색 결과를 구조화해 받을 수 있어 검색 DOM 유지보수 범위를 줄임 | 공급자 계약·인증·할당량·이용료 조건, 원본 사이트의 다운로드 실패는 남음 | 반복 대량 운영이 필요하면 별도 검토 |
| Google Custom Search JSON API | 기존 이미지 검색 인터페이스 제공 | 신규 고객 이용 불가, 2027-01-01 종료 | 신규 기능에서는 제외 |

외부 API의 실제 예로 SerpApi는 썸네일, 원본 이미지 URL, 원본 제공 페이지 URL을 서로 다른 필드로 반환한다. 이 초안은 특정 업체의 계약이나 유료 API 사용을 승인하거나 자동으로 전환하는 설계가 아니다.

## 3. 첫 배포 범위

첫 배포에 포함할 항목:

1. 검색엔진 선택: 네이버 또는 구글.
2. 두 엔진에서 공통으로 사용하는 단일 검색과 CSV/XLSX 검색.
3. 구글의 고해상도 이미지 저장을 기본으로 제공하고 썸네일 대체는 사용자가 선택한다.
4. PNG 저장, 제작 용도별 크기 프리셋과 실제 이미지 크기 검사, 정확히 동일한 이미지 중복 제거.
5. 엔진과 실행별 출력 분리, 기존 결과 보존.
6. 성공·부분 성공·실패·검색 결과 없음·사용자 확인 필요·중단 상태 구분.
7. 진행률, 중단 요청, 실행 결과 열기, 결과 목록에서 이미지 파일과 출처 페이지 열기.
8. 기존 네이버 수집에서 확인한 폴더 충돌, 0장 성공, 조기 스크롤 종료 문제 해결.

후속 배포로 분리할 항목:

- 네이버와 구글을 한 번에 선택하는 통합 실행.
- 프로그램 재시작 후 이어받기와 실패 작업만 재실행.
- 이미지 미리보기 갤러리와 선택 다운로드. 첫 버전에는 간단한 결과 목록과 파일·출처 열기를 제공한다.
- 외부 검색 API 수집기.
- 유사 이미지 판별과 워터마크 탐지.
- 검색 기간·사용 권한 등 고급 필터. 구현 전에 엔진별 지원을 확인한다.

첫 버전부터 모든 기능을 넣는 대신, 구글 수집과 두 엔진의 저장 신뢰성을 먼저 검증한다.

## 4. 구조

~~~mermaid
flowchart TD
    A[GUI 또는 CLI] --> B[작업 실행기]
    B --> C[네이버 수집기]
    B --> D[구글 수집기]
    C --> E[공통 이미지 후보]
    D --> E
    E --> F[다운로드와 이미지 검사]
    F --> G[실행별 저장과 메타데이터]
    B --> H[진행 이벤트와 결과 요약]
~~~

각 구성요소의 책임:

| 구성요소 | 책임 | 의존성 |
| --- | --- | --- |
| models.py | 검색 옵션, 후보, 저장 결과, 작업 상태 정의 | 표준 라이브러리 |
| providers/base.py | 검색엔진 공통 계약과 지원 기능 정의 | models |
| providers/naver.py | 기존 네이버 검색·후보 추출 | Selenium, models |
| providers/google.py | 구글 검색·카드·상세 미리보기에서 후보 추출 | Selenium, models |
| browser.py | Chrome 생성, 실행 중 재사용, 종료 | Selenium, webdriver-manager |
| downloader.py | URL 선택, 전송, 실제 이미지 검사, PNG 변환, 중복 판정 | requests, Pillow |
| storage.py | 실행 폴더, 파일 확정, 메타데이터, 작업 기록 | 표준 라이브러리 |
| runner.py | 키워드 순서, 엔진 선택, 저장 목표, 시간 제한, 중단·실패 처리 | provider 계약, downloader, storage |
| batch_input.py | 기존 CSV/XLSX 검증과 키워드 로딩 | csv, openpyxl |
| gui.py / cli.py | 사용자 입력과 결과 표시 | runner, batch_input |

naver_image_collector.py는 기존 실행 명령을 유지하는 진입점으로 남긴다. 실제 구현은 image_collector 패키지로 분리한다. 단순한 검색엔진 URL 변경이나 기존 함수 안의 엔진별 조건문 증설로 확장하지 않는다.

공통 수집기 계약은 검색어와 검색 옵션을 받아 후보를 순서대로 제공하는 방식이다. 후보 수집기는 이미지를 저장하지 않는다. 다운로드·파일 이름·메타데이터 작성은 공통 계층에서 처리한다.

브라우저는 작업 스레드가 소유한다. 일괄 실행 안에서 동일한 Chrome을 재사용하고, 시작·성공·실패·중단 모두 최종 정리 경로에서 Chrome과 HTTP 세션을 종료한다. 동일한 WebDriver를 여러 스레드에서 동시에 조작하지 않는다.

## 5. 사용자 흐름과 기본값

사용 흐름:

1. 네이버 또는 구글을 선택한다.
2. 검색어를 입력하거나 CSV/XLSX를 선택한다.
3. 일괄 입력은 유효 키워드 수와 앞부분 미리보기를 표시한다.
4. 이미지 수, 제작 용도 프리셋, 저장 방식, 실제 크기 기준, 저장 위치를 확인한다.
5. 수집 시작 후 현재 키워드와 저장·제외·실패 수를 확인한다.
6. 작업 완료 후 결과 목록에서 파일명·실제 크기·저장 방식·출처를 확인한다.
7. 후보 이미지 파일 또는 출처 페이지를 열어 제작에 사용할 이미지를 선택한다.

| 항목 | 기존 네이버 기본값 | 구글 기본 제안 |
| --- | --- | --- |
| 목표 저장 수 | 50장 | 50장 |
| 최소 이미지 크기 | 가로·세로 각각 150px | 블로그 프리셋: 긴 변 1200px 이상, 가로·세로 각각 150px 이상 |
| 다운로드 방식 | 썸네일 | 고해상도 이미지 저장, 썸네일 대체 기본 꺼짐 |
| 저장 형식 | PNG | PNG |
| 브라우저 | 기존 숨김 옵션 유지 | 초기 배포는 브라우저 표시 권장 |
| 검색 정렬 | 기존 최신순 요청 유지 | 관련도 기본값 |

구글에 네이버의 최신순 파라미터를 그대로 적용하지 않는다. 날짜 필터는 후속 기능이며, 검색 결과의 날짜를 이미지 촬영일·EXIF 날짜로 해석하지 않는다.

CLI에는 --engine naver 또는 --engine google을 추가한다. 엔진을 생략하면 네이버로 동작한다. 다운로드 모드는 --download-mode thumbnail, original-preferred, original-only로 구분한다. 생략 시 네이버는 thumbnail, 구글은 original-only를 적용하고 실제 적용값을 실행 요약에 기록한다.

제작 용도 프리셋은 다음 값을 제안한다. 업계의 필수 기준이 아니라 앱의 선택 가능한 설정값이다.

| 프리셋 | 이미지 검사 기준 | 용도 |
| --- | --- | --- |
| 블로그 | 긴 변 1200px 이상, 가로·세로 각각 150px 이상 | 글에 삽입할 고해상도 이미지 후보 |
| 가로 영상 | 가로 1920px 이상, 세로 1080px 이상 | Full HD 화면을 채울 이미지 후보 |
| 세로 영상 | 가로 1080px 이상, 세로 1920px 이상 | 세로 영상 화면을 채울 이미지 후보 |
| 기존 썸네일 | 가로·세로 각각 150px 이상 | 기존 네이버 사용과 작은 이미지 자료 |
| 사용자 지정 | 사용자가 지정한 최소 가로·세로·긴 변 | 일부 화면에 삽입할 자료 등 다른 용도 |

프리셋은 실제 픽셀 크기로 검사하며 자동 확대·크롭·화면비 변경을 하지 않는다. 영상 전체 화면을 채우는 크기와 영상 일부에 삽입할 이미지 크기를 같은 요구사항으로 취급하지 않는다.

GUI와 CLI는 profile 및 적용된 최소 가로·세로·긴 변 값을 실행 기록에 저장한다. 구글의 기본 프로필은 blog이고, 네이버의 기존 실행은 legacy-thumbnail이다. 썸네일 모드를 명시적으로 고르면 별도 프로필 지정이 없는 경우 legacy-thumbnail을 적용한다. 크기 옵션을 명시적으로 수정하면 사용자 지정 프로필로 표시하며 변경하지 않은 기준은 선택한 프로필 값을 유지한다.

첫 버전에서 네이버는 기존 썸네일 수집을 유지한다. 네이버 수집기가 고해상도 URL을 제공하도록 검증되기 전에는 고해상도 전용 옵션을 비활성화하고, CLI에서도 미지원 조합을 실행 전에 안내한다.

새 저장 레이아웃은 버전 변경 사항으로 README에 명시한다. 기존 폴더의 이미지를 자동 이동하거나 삭제하지 않는다.

## 6. 구글 후보 수집

구글 수집은 다음 순서로 설계한다.

1. 구글 이미지 결과 페이지를 연다.
2. 결과 영역 또는 명시적인 결과 없음·동의·사용자 확인 화면을 기다린다.
3. 결과 카드 범위에서 후보를 찾는다. 전체 페이지의 모든 img를 다운로드 대상으로 사용하지 않는다.
4. 썸네일, 제목, 검색 순위를 읽는다.
5. 고해상도 모드에서는 해당 결과를 선택하고 상세 미리보기가 바뀌어 로딩될 때까지 기다린다.
6. 제공된 고해상도 이미지 URL과 출처 페이지 URL을 구분해 읽는다.
7. 로고, 관련 검색 아이콘, 광고·추천 영역 등 결과 카드 밖의 이미지는 제외한다.
8. 유효하게 저장된 이미지 수가 목표에 도달하거나 종료 조건에 도달할 때까지 추가 후보를 가져온다.

구체적인 구글 URL 파라미터와 선택자는 현재 설계에서 확정하지 않는다. 구현 첫 단계에서 실제 화면을 관찰해 결과 카드, 상세 미리보기, 동의 화면, 차단 화면을 확인하고 샘플 DOM을 기반으로 결정한다. 공개 문서만으로 현재 DOM 수집 성공을 보장할 수 없다.

조건 대기를 사용한다. 단순 고정 sleep으로 화면 로딩 완료를 판정하지 않는다. 스크롤 뒤 후보를 다시 추출한 다음 이전의 고유 후보 수와 비교한다.

기본 종료 조건:

- 유효하게 저장한 이미지가 요청 수에 도달함.
- 재추출해도 고유 후보가 3회 연속 증가하지 않음.
- 최대 30회 스크롤, 후보 수 max(100, 요청 수 × 5), 키워드 작업 시간 300초 중 하나에 도달함.
- 사용자 중단 또는 사용자 확인 화면을 감지함.

이 값은 제안한 운영 기본값이다. 실측 검증 후 설정값으로 조정하되, 제한 없이 스크롤하거나 재시도하지 않는다.

## 7. 다운로드 품질과 검사

다운로드 모드:

| 모드 | 동작 |
| --- | --- |
| thumbnail | 썸네일을 저장한다. |
| original-preferred | 유효한 고해상도 URL을 먼저 시도하고 실패·미노출·미지원 시 썸네일을 검사해 대체한다. |
| original-only | 고해상도 URL에서 검사에 통과한 이미지만 저장한다. 썸네일로 대체하지 않는다. |

여기서 original은 검색 결과가 제공한 이미지 URL을 의미한다. 업로더의 최초 원본이나 최대 해상도를 보장하지 않는다. PNG 저장은 디코딩 후 재저장하므로 원본 바이트를 그대로 보존한다는 뜻도 아니다. 구글의 기본 화면에는 “고해상도 이미지 저장”을 표시하고 “실패 시 썸네일 대체”는 기본 꺼짐 옵션으로 제공한다.

제작용 수집에서는 목표 수를 채우기 위해 고해상도 실패 후보를 자동으로 저해상도 이미지로 바꾸지 않는다. 썸네일 대체를 사용자가 켰을 때만 original-preferred를 적용하고, 결과 목록과 요약에서 대체 저장을 구분한다.

- 고해상도 다운로드 실패와 대체 저장 성공을 각각 기록한다.
- 썸네일로 대체할 때도 사용자가 지정한 최소 가로·세로·긴 변 기준을 적용한다. 대체를 켰다는 이유로 제작용 크기 기준을 자동으로 낮추지 않는다.
- 작은 썸네일을 확대해 최소 크기 검사를 통과시키지 않는다.
- 실제 디코딩 결과의 가로·세로와 파일 형식을 기록한다.
- 첫 버전의 입력 지원은 JPEG·PNG·WebP로 제한하고 PNG로 저장한다. 미지원 형식은 명시적으로 제외한다.
- 고해상도 다운로드 URL은 HTTP/HTTPS를 사용한다. file, blob, x-raw-image 등 다운로드 불가능한 주소는 원본 후보로 사용하지 않는다.
- 구글이 제공하는 썸네일이 data:image 형태이면 JPEG/PNG/WebP의 제한된 크기 데이터만 디코딩하는 별도 경로를 둔다. 이를 requests에 넘기지 않는다.
- HTML 오류 페이지를 이미지로 저장하지 않는다. Content-Type과 Pillow 디코딩 결과를 확인한다.
- 이미지 크기·전송량 제한을 적용한다. 첫 설정은 다운로드 20MB, 디코딩 40MP로 제안하며 초과 시 기록 후 다음 후보로 진행한다.

중복 제거는 같은 키워드·같은 엔진·같은 실행 안에서 동일한 크기의 RGBA 픽셀 해시로 판정한다. URL만 비교하지 않는다. 크기가 다른 이미지나 JPEG 압축 차이까지 같은 이미지로 묶는 유사 이미지 판별은 후속 기능이다.

## 8. 파일과 메타데이터

출력 레이아웃:

~~~text
downloaded_images/
  run_20261013T025141Z_<실행식별자>/
    run.json
    batch_summary.csv
    kw_<짧은검색어>_<검색어해시>/
      naver/
        image_01.png
        metadata.csv
        metadata.json
      google/
        image_01.png
        metadata.csv
        metadata.json
~~~

첫 버전에서는 선택한 엔진 폴더만 만든다. 같은 run_id에 두 엔진을 담는 구조는 후속 통합 실행에도 사용한다.

- run_id는 UTC 시각과 무작위 식별자를 사용해 새 실행을 구분한다.
- 폴더명은 kw_ 접두사, 길이를 제한한 검색어, 공백을 정리한 실제 검색어의 해시를 조합한다.
- 문장부호 제거, 이름 길이 제한, Windows 예약 이름·대소문자 규칙 때문에 다른 키워드가 같은 폴더에 저장되지 않도록 한다.
- 기존 결과를 먼저 삭제하는 clear_generated_images 흐름을 사용하지 않는다.
- 파일은 .part에 기록한 뒤 이미지 검증과 PNG 변환을 완료한 후 최종 이름으로 확정한다.
- 이미지 한 장을 확정할 때마다 해당 작업의 JSON 기록을 임시 파일 교체 방식으로 갱신한다. CSV는 작업 종료·중단 시 JSON 기록에서 생성한다.
- 두 파일을 동시에 원자적으로 저장한다고 가정하지 않는다. CSV와 JSON이 불일치하면 JSON을 기준으로 CSV를 재생성한다.
- 새 실행에서 실패해도 이전 실행의 이미지와 메타데이터는 보존한다.

기존 메타데이터 열은 유지하며 다음 정보를 추가한다.

| 필드 | 의미 |
| --- | --- |
| schema_version, run_id, engine | 형식 버전·실행·검색엔진 |
| candidate_id, search_rank | 후보 식별자·검색 결과 순위 |
| original_url | 검색 결과가 제공한 이미지 파일 URL. 없으면 null |
| source_url | 이미지가 실린 페이지 URL. 확인되지 않으면 빈 값 |
| downloaded_url, download_kind | 실제 다운로드 대상과 original/thumbnail 구분 |
| width, height, format, byte_size | 실제 저장 이미지 검사 결과 |
| content_hash | 저장 대상 이미지의 중복 판정 해시 |
| collected_at | UTC ISO 8601 수집 시각 |
| profile, min_width, min_height, min_long_edge | 선택한 제작 용도와 적용한 실제 크기 기준 |
| fallback_reason | 고해상도 다운로드 대신 썸네일을 저장한 이유 |
| license_url, license_status | 제공된 라이선스 링크와 확인 상태 |

사용 권한 정보가 없는 후보는 license_status=unknown이다. 정보가 노출되면 provided로 기록하며, 앱이 자동으로 commercial_use_allowed 같은 결론을 만들지 않는다. 결과 목록에서 출처 및 제공된 라이선스 링크를 열 수 있게 해 게시 전에 필요한 원본 정보를 확인할 수 있도록 한다.

## 9. 오류·중단·상태

작업 상태를 다음처럼 정의한다.

| 상태 | 판정 |
| --- | --- |
| success | 요청한 유효 이미지 수를 저장함 |
| partial | 1장 이상 저장했으나 요청 수에 못 미치고 일반 종료 조건에 도달함 |
| empty | 수집기가 명시적으로 정상 검색 결과 없음을 확인함 |
| failed | 결과 구조 인식 실패·브라우저 오류·저장 실패 또는 후보가 있지만 유효 저장이 0장임 |
| needs_attention | 동의·확인 화면·비정상 트래픽 등으로 사용자 처리가 필요함 |
| cancelled | 사용자 중단 요청으로 종료함 |

사용자 확인·중단 상태는 이미 저장한 장수가 있더라도 해당 상태로 기록하고 saved_count를 함께 표시한다. 차단을 partial 또는 empty로 숨기지 않는다. 검색 결과 구조를 읽지 못한 것을 정상적인 검색 결과 없음으로 처리하지 않는다.

- 개별 다운로드의 일시적 네트워크 오류와 5xx에는 제한된 재시도를 적용한다. 총 시도는 최대 3회다.
- 404·지원하지 않는 형식·작은 이미지에는 같은 URL 재시도를 하지 않는다.
- 429에는 Retry-After를 반영하며, 작업 시간 범위 안에서 대기할 수 없으면 기록 후 멈춘다.
- 다른 호스트의 이미지를 받아야 하므로 공통 Naver Referer를 모든 요청에 사용하지 않는다. 실제 출처 맥락에 맞게 처리한다.
- Google 사용자 확인 화면을 감지하면 요청을 멈추고 현재 결과와 사유를 남긴다.
- 표시 브라우저에서는 사용자가 확인 화면을 처리한 뒤 같은 실행을 계속할 수 있게 한다. 숨김 모드에서는 작업 기록을 남기고 재실행 안내를 표시한다.
- 키워드 실패는 다음 키워드 실행을 막지 않지만, 엔진 수준 차단은 그 엔진의 나머지 검색을 계속 반복하지 않는다.

GUI는 queue와 메인 스레드의 주기적 이벤트 처리를 사용한다. 작업 시작 전에 GUI 변수 값을 일반 값으로 복사한다. 작업 스레드에서 Tkinter 변수나 위젯을 직접 읽고 변경하지 않는다.

중단 요청은 후보 처리 경계, 조건 대기, 다운로드 경계에서 확인한다. 연결·읽기 타임아웃을 설정하고, 진행 중 요청 때문에 즉시 중단되지 않으면 “중단 중” 상태를 표시한다. GUI를 닫을 때도 이벤트와 브라우저를 정리한다.

CLI 결과 요약은 각 상태를 분리해 표시한다. failed 또는 needs_attention이 있으면 0이 아닌 종료 코드를 반환한다. partial/empty만 있는 실행은 정상 종료하되 수량 부족을 요약과 메타데이터에 표시한다. 중단은 별도 중단 종료 코드로 구분한다.

## 10. 후속 통합 실행과 이어받기 방향

두 엔진 통합 실행은 초기에는 순차 처리한다. 같은 WebDriver를 동시에 사용하지 않는다.

“엔진별 50장”처럼 목표 수의 기준을 화면에 명시한다. 두 엔진이면 최대 100장을 목표로 하며, 결과 부족과 중복 때문에 실제 수량은 달라질 수 있다. 키워드당 합계 50장에 두 엔진을 섞는 할당 방식은 별도 옵션으로 다룬다.

이어받기는 기존 run_id를 명시적으로 선택하는 작업이다. 새 실행을 자동으로 이전 실행에 섞지 않는다.

- 엔진·키워드·모드·프로필·실제 크기 옵션이 맞는 작업만 이어받는다.
- 기존 완료 이미지를 검증하고 고유 식별자·해시를 읽는다.
- 확정 파일과 JSON 기록 사이에서 중단된 저장은 검증 후 재등록 또는 재다운로드한다.
- 완료 작업은 건너뛰고 미완료·실패 작업을 선택 재실행한다.
- 기본 흐름은 파일 기반 기록을 사용한다. 데이터 규모 때문에 필요해질 때 SQLite를 검토한다.

## 11. 검증 기준과 배포 순서

### 첫 단계: 공통 저장 안정성

네이버 동작을 유지하면서 모델, 다운로드, 저장, 실행기 책임을 분리한다.

기존 20개 테스트와 다음 재현 사례를 자동 검증한다.

- 검색 실패 시 기존 결과가 보존된다.
- a/b와 a b, 긴 이름, Windows 예약 이름, 대소문자가 다른 키워드가 충돌하지 않는다.
- 저장 0장이 success로 집계되지 않는다.
- 새 후보가 늘면 스크롤이 조기에 종료되지 않는다.

### 두 번째 단계: 구글 실제 화면 확인과 수집기

실제 구글 화면에서 결과·동의·확인·빈 검색의 상태를 확인한다. DOM 샘플을 확보해 후보 추출과 페이지 상태 분류의 회귀 검증에 사용한다.

확인할 기준:

- 결과 카드 밖의 이미지가 제외된다.
- source_url과 original_url을 혼동하지 않는다.
- 상세 이미지가 바뀌기 전에 이전 후보의 이미지를 읽지 않는다.
- 조건 대기·재추출·차단 인식에 종료 조건이 있다.
- 네이버와 구글 수집기가 같은 후보 계약을 만족한다.

DOM 확인 후 고해상도 URL을 안정적으로 제공받을 수 없으면 해당 후보를 원본 미노출로 기록한다. 구현 완료 전에 썸네일만 가능한 상태와 고해상도 모드의 실제 지원 범위를 사용자에게 명확히 보여준다.

### 세 번째 단계: GUI·CLI와 다운로드 품질

다운로드 검증은 외부 사이트에 의존하지 않는 테스트 서버와 이미지 샘플을 사용한다.

- 원본 다운로드 성공, 403/404/타임아웃, 썸네일 대체, original-only 제외.
- HTML 응답, 작은 이미지, 미지원 주소, 큰 파일, 손상 이미지.
- 서로 다른 URL의 동일 이미지 중복 제거.
- PNG 형식, 실제 크기, 원본·대체 여부와 오류 기록.
- 구글 기본값이 original-only이며, 썸네일 대체를 사용자가 켠 경우에만 대체를 시도한다.
- 블로그·가로 영상·세로 영상의 경계 크기와 가로·세로 방향을 정확히 검사한다.
- 썸네일 대체를 켜도 제작용 크기 기준은 유지하며 작은 이미지를 확대해 통과시키지 않는다.
- 결과 목록의 이미지·출처·라이선스 링크가 올바른 후보에 연결되고, 원본 저장 수와 썸네일 대체 수를 별도로 집계한다.
- 중단 및 창 종료 시 파일 기록과 리소스 정리.
- CSV UTF-8/CP949, 중복·빈 행, XLSX의 기존 처리 유지.
- partial/failed/empty/needs_attention와 CLI 종료 코드.

실제 수집은 소량으로 검증한다. 한글 인물명, 영문 물건명, 구체적인 장소명 각 1개에 대해 엔진별 10장 목표로 확인하고, 이후 구글 3개 키워드 일괄 실행과 수집 중단을 확인한다.

완료 기준은 요청 수만큼 항상 저장하는 것이 아니다. 실제 유효 이미지 수, 부족 사유, 출처, 저장 방식과 작업 상태를 정확하게 보여주는 것이다. 사이트 차단 시 무인 성공을 주장하지 않는다.

### 후속 배포

첫 배포의 결과를 확인한 뒤 통합 실행·이어받기·실패 재실행·갤러리·외부 API 연동을 별도 변경으로 진행한다. 무료 브라우저 수집이 실제 수집량에 맞지 않으면 외부 API 방식으로 전환하는 비용과 운영 조건을 비교한다.
